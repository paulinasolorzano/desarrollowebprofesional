2 Conceptos clave que debes conocer
🔄 De la forma inline al patrón MVC — ¿qué cambió y por qué?

En la Práctica 2 escribiste el endpoint /api/health directamente en server.js con una función anónima inline. Eso funciona perfectamente y no tiene nada de malo para casos simples.

El problema aparece cuando el sistema crece. Imagina escribir los cinco endpoints de personas, más los cinco de usuarios, más los de proyectos y tareas — todo en el mismo archivo. El resultado sería un server.js de más de 400 líneas donde la configuración del servidor, las consultas SQL y la lógica de negocio están completamente mezcladas.

Compara ambos enfoques para el mismo endpoint GET /api/personas:

❌ Sin MVC — todo en server.js
✅ Con MVC — separado en archivos

El código que se ejecuta es idéntico. La diferencia es solo de organización: dónde vive cada pieza y quién es responsable de qué.

Analogía: Es como tener todos tus documentos de trabajo, facturas, contratos y notas personales en una sola carpeta sin subcarpetas. Funciona cuando tienes 10 archivos. Con 200 se vuelve inmanejable. MVC son las subcarpetas.

🏢 ¿server.js ya no tiene endpoints? ¿Desaparecen?

No desaparecen. Todos los endpoints siguen siendo accesibles desde Thunder Client y desde el navegador exactamente igual. Lo que cambia es dónde está escrita la lógica, no si el endpoint existe o no.

server.js tiene ahora tres responsabilidades claras:

🏗️ Las tres capas de MVC aplicadas a esta API

MVC son las siglas de Modelo, Vista y Controlador. En una API REST la "Vista" no existe como tal (no hay HTML), así que el patrón se adapta así:

Modelo (datos)
db.js
Conexión a MySQL.
Pool de conexiones.
No contiene consultas — solo la conexión disponible para quien la pida.
Controlador (lógica)
personas.controller.js
Funciones que ejecutan las consultas SQL, procesan los datos y construyen la respuesta JSON.
Router (enrutamiento)
personas.routes.js
Conecta cada URL + verbo HTTP con la función del controlador. No contiene lógica de negocio.

🔁 ¿Qué es CRUD?

CRUD son las cuatro operaciones básicas sobre cualquier conjunto de datos. Cada operación se mapea a un verbo HTTP y a una sentencia SQL:

Letra Operación Verbo HTTP SQL equivalente
CCreate — crearPOSTINSERT
RRead — leer / listarGETSELECT
UUpdate — actualizarPUTUPDATE
DDelete — eliminarDELETEUPDATE activo=0 (soft)
📨 req.params y req.body — cómo llegan los datos al controlador

Cuando la URL incluye un valor variable como /api/personas/5, Express lo captura con /:id en la ruta. Dentro del controlador lo lees con req.params.id.

Cuando el cliente envía datos JSON en el cuerpo de la petición (los campos de una nueva persona), llegan en req.body. El middleware express.json() de la Práctica 2 es el que los convierte automáticamente en un objeto JavaScript.

Analogía: req.params es el número de mesa que viene en el pedido. req.body es la nota con todos los platillos que quiere esa mesa.
🛡️ Placeholders ? — prevención de SQL Injection

Nunca concatenes valores directamente en una cadena SQL. Esto abre una vulnerabilidad llamada SQL Injection: un atacante manipula el valor para ejecutar cualquier sentencia SQL en tu base de datos.

❌ Vulnerable — nunca hacer esto
✅ Seguro — usar siempre placeholders

La librería mysql2 sanea automáticamente cada valor antes de enviarlo a MySQL.

4 Endpoints a construir

El módulo de Personas tendrá cinco endpoints. Todos se montan bajo el prefijo /api/personas que se registra en server.js con una sola línea.

VerboURL completaFunción en controladorDescripciónCódigo
GET/api/personasgetAllLista todas con activo = 1200
GET/api/personas/:idgetByIdObtiene una persona por id200 / 404
POST/api/personascreateCrea una nueva persona201
PUT/api/personas/:idupdateActualiza datos de una persona200 / 404
DELETE/api/personas/:idsoftDeleteMarca como inactiva (activo = 0)200 / 404
¿Por qué soft delete? Si eliminaras con DELETE SQL, MySQL lo bloquearía por las llaves foráneas (RESTRICT) porque proyectos y tareas apuntan a personas. Además perderías el historial. El soft delete resuelve ambos problemas marcando el registro como inactivo sin tocarlo.

6 Desarrollo paso a paso
Paso 1Crear el controlador de personas

Crea controllers/personas.controller.js. Este archivo exporta cinco funciones con nombre — la misma estructura (req, res) => {} que usaste inline en la Práctica 2, pero ahora cada función tiene un nombre y usa async/await para consultar MySQL.

📄 /controllers/personas.controller.js — NUEVO
 
 
¿Por qué export const en lugar de export default? Usamos exportaciones nombradas porque el controlador tiene múltiples funciones. Con exportaciones nombradas puedes importar exactamente las que necesitas: import { getAll, getById } from '...'. Con export default solo puedes exportar un valor por archivo.
Paso 2Crear las rutas de personas

Crea routes/personas.routes.js. Este archivo no contiene ninguna lógica: solo conecta cada combinación verbo+URL con su función del controlador. Nota que las rutas usan '/' y '/:id', no '/personas' — el prefijo /api/personas lo pone server.js.

📄 /routes/personas.routes.js — NUEVO
¿Por qué las rutas no incluyen /personas? Porque el router solo conoce la parte de la URL que viene después del prefijo registrado en server.js. Esto permite cambiar el prefijo de /api/personas a /v2/personas modificando una sola línea en server.js sin tocar el router.
Paso 3Registrar las rutas en server.js

Abre server.js y agrega solo estas dos líneas. El archivo sigue siendo el mismo de la Práctica 2 — solo incorporas el import y el registro del router. El endpoint /api/health se queda exactamente igual, inline, como estaba.

📄 server.js — agregar solo estas 2 líneas (el resto no cambia)
¿Cómo funciona app.use() con un router? Cuando llega una petición a /api/personas/3, Express detecta que el prefijo coincide con /api/personas, le corta esa parte y le pasa /3 al router. El router lo reconoce como /:id y llama a getById. El cliente nunca nota esta delegación interna.

8 Preguntas de reflexión

  4. Si en lugar de export const getAll usaras export default, ¿cómo cambiaría la forma de importar la función en el archivo de rutas?
