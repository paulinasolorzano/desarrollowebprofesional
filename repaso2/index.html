1 useState y useEffect — estado y efectos secundarios
1
¿Por qué React necesita un hook especial (useState) para guardar datos, en lugar de simplemente usar una variable normal de JavaScript? useState
💭 Piensa: ¿qué pasa con una variable normal cuando React vuelve a renderizar el componente?
Conecta con el proyecto: En PersonaForm.jsx tienes const [form, setForm] = useState(vacío). ¿Qué pasaría si guardaras los campos del formulario en una variable let form = {} en lugar de con useState?
2
En el proyecto tienes useEffect(() => { cargarPersonas(); }, []) y en otro lugar useEffect(() => { getPersonaById(id) }, [id]). ¿Cuál es la diferencia real entre poner [] y poner [id]? useEffect
💭 ¿Qué problema concreto se resolvería si no pusieras el id en el arreglo de dependencias?
Escenario real: El usuario va a /personas/editar/3, edita y guarda. Luego hace clic en ✏️ de otra persona — la URL cambia a /personas/editar/7. ¿Qué ocurriría con el formulario si el useEffect no tuviera [id] en su arreglo de dependencias?
3
Cuando haces setForm({ ...form, [e.target.name]: e.target.value }), estás usando el operador spread. ¿Por qué no puedes simplemente hacer form.nombre = e.target.value directamente? useState
💭 Investiga qué significa "inmutabilidad del estado" en React y por qué existe esa regla.
Pista: React compara el estado anterior con el nuevo para decidir si necesita re-renderizar. Si mutas el objeto directamente, ¿cómo sabe React que algo cambió?
2 React Router DOM — navegación entre pantallas
4
¿Por qué en el Navbar usamos <Link to="/personas"> en lugar de <a href="/personas">? Ambos te llevan a la misma URL, pero uno destruye el trabajo de React. ¿Cuál y por qué? React Router
💭 ¿Qué hace el navegador cuando procesa un <a href>? ¿Qué hace React Router con Link en su lugar?
Prueba en el proyecto: Cambia temporalmente un Link por <a href> y navega. ¿Notas algo diferente? ¿Qué pasa con el estado de la aplicación?
5
En App.jsx tienes la ruta path="/personas/editar/:id" y en PersonaFormPage.jsx tienes const { id } = useParams(). ¿Por qué id llega como string "3" y no como número 3? ¿Dónde importa esa diferencia en el código? useParams
💭 Si pasas ese id directamente a una consulta SQL como WHERE id = ?, ¿importa que sea string o número?
Investiga: Busca qué hace parseInt(id) y Number(id). ¿En qué casos del proyecto necesitarías convertir el tipo?
3 Context API, PrivateRoute y cookies httpOnly
6
El AuthProvider necesita estar dentro del BrowserRouter en main.jsx. ¿Qué error concreto ocurriría si los inviertes — es decir, si pones BrowserRouter dentro de AuthProvider? Context
💭 Dentro de AuthContext usamos useNavigate(). ¿Qué necesita ese hook para funcionar?
Pista: useNavigate() solo funciona dentro del árbol de componentes de un BrowserRouter. Si AuthProvider estuviera por encima del BrowserRouter, ¿qué pasaría cuando AuthContext llame a useNavigate()?
7
Si guardas el JWT en localStorage, un script malicioso puede robarlo con localStorage.getItem('token'). Pero si usas una cookie httpOnly, ese mismo script no puede leerla. ¿Por qué? ¿Qué hace el atributo httpOnly exactamente? Seguridad
💭 Prueba en la consola del navegador: escribe document.cookie después de hacer login. ¿Ves el token? ¿Por qué no?
Investiga: Busca qué es un ataque XSS (Cross-Site Scripting) y cómo una cookie httpOnly lo mitiga. Escribe en la libreta un ejemplo de código XSS que robaría el token de localStorage pero fallaría con httpOnly.
8
Cuando el usuario recarga la página, React pierde todo su estado — incluyendo el objeto usuario del contexto. Sin embargo la sesión se recupera automáticamente sin pedir login de nuevo. ¿Cómo funciona ese mecanismo en el proyecto? Context Seguridad
💭 Revisa el useEffect dentro de AuthProvider. ¿Qué hace al montar? ¿Qué endpoint llama y por qué puede saber si hay sesión activa?
Traza el flujo: Al recargar → AuthProvider monta → useEffect ejecuta → llama a GET /api/auth/me → el navegador envía la cookie automáticamente → el backend verifica el JWT en la cookie → responde con los datos del usuario → setUsuario() restaura el estado. Escribe ese flujo completo en la libreta.
4 Axios, arquitectura y patrones del proyecto
9
En el proyecto todas las llamadas HTTP están encapsuladas en src/api/personas.api.js y los componentes importan funciones de ahí en lugar de usar axios directamente. ¿Qué ventaja concreta tiene eso cuando el backend cambia, por ejemplo, de /api/personas a /api/v2/personas? Axios Patrón
💭 ¿Cuántos archivos tendrías que modificar en cada caso: con el módulo de API centralizado vs sin él?
Cuenta los archivos: Sin el módulo centralizado, axios.get estaría en PersonasPage, PersonaFormPage, Navbar… Con el módulo, ¿en cuántos archivos cambiarías la URL?
10
El componente PersonaFormPage.jsx maneja dos casos con el mismo código: crear una persona nueva y editar una existente. La única diferencia es si id existe en la URL o no. ¿Es eso buena práctica o deberían ser dos componentes separados? Argumenta con pros y contras. Patrón
💭 ¿Qué pasa cuando el formulario de editar necesita mostrar campos extra que no aparecen al crear? ¿Cómo lo resolverías sin duplicar todo el formulario?
Investiga: Busca el concepto "single responsibility principle" (principio de responsabilidad única) y evalúa si PersonaFormPage lo cumple. No hay una respuesta única correcta — lo importante es que argumentes.
