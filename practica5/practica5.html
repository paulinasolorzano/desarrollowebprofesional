2 Conceptos clave: React Router DOM y props
🗺️ ¿Qué es React Router DOM?

React por sí solo no sabe nada de URLs ni de navegación entre páginas. React Router DOM es la biblioteca que agrega esa capacidad: le dice a React qué componente mostrar dependiendo de la URL actual del navegador.

Sin React Router, si el usuario escribe /personas/nueva en la barra del navegador, React no sabría qué mostrar. Con React Router, defines reglas como: "cuando la URL sea /personas/nueva, muestra el componente PersonaFormPage".

Analogía: React Router es como el sistema de señalización de un edificio. El edificio (React) ya existe con todas sus habitaciones (componentes). El sistema de señalización (Router) decide qué habitación se muestra dependiendo del número de piso que pides (la URL).
🔗 Los 4 elementos de React Router que usarás
Elemento¿Para qué sirve?Equivalente HTML
BrowserRouterEnvuelve toda la app. Activa el sistema de rutas.—
RoutesContenedor de todas las rutas. Solo muestra la que coincide.switch/case
RouteDefine una regla: si la URL es X, muestra el componente Y.case

¿Por qué no usar <a href> normal? Porque un <a href> hace una recarga completa del navegador, borrando todo el estado de React. Link cambia la URL sin recargar, manteniendo la app viva.
📬 ¿Qué son los props?

Los props (propiedades) son la forma en que un componente padre le pasa información a un componente hijo. Son como los parámetros de una función: el padre los define, el hijo los recibe.

En esta práctica el componente PersonaFormPage recibirá el id de la persona a editar directamente de la URL gracias al hook useParams, que extrae los segmentos dinámicos de la ruta (/personas/editar/:id → id = 3).

Analogía: Los props son como un formulario que llenas antes de entrar a una oficina. Le dices al componente exactamente qué datos necesita para hacer su trabajo. Sin props, el componente no sabe con qué información debe trabajar.
🧭 Hook useNavigate: navegar desde el código

A veces necesitas navegar a otra ruta desde dentro de una función, no desde un botón de enlace. Por ejemplo: después de guardar un formulario exitosamente, quieres redirigir automáticamente al listado.

useNavigate es el hook que permite hacer eso: navigate('/personas') lleva al usuario a esa ruta sin que él tenga que hacer clic en nada.

Analogía: Es como la redirección automática después de completar un trámite en ventanilla. Tú terminas de firmar (guardar el formulario) y la ventanilla te indica automáticamente que pases a la siguiente área (listado).

Paso 2Activar el Router en main.jsx

BrowserRouter debe envolver a toda la aplicación para que el sistema de rutas funcione en cualquier componente. El lugar correcto para ponerlo es main.jsx, que es el punto de entrada:

src/main.jsx — agregar BrowserRouter
¿Por qué en main.jsx y no en App.jsx? Porque BrowserRouter necesita envolver todo, incluyendo a App.jsx. Si lo pusiéramos dentro de App.jsx, estaría dentro de sí mismo. Al ponerlo en main.jsx garantizamos que toda la jerarquía de componentes tiene acceso al sistema de rutas.

Observa la estructura: Routes contiene varios Route. Cada Route tiene un path (la URL) y un element (el componente que se muestra). El Navbar está fuera de Routes para que aparezca en todas las páginas.

💡 El parámetro dinámico :id — en la ruta /personas/editar/:id, los dos puntos indican que id es un valor variable. Si el usuario va a /personas/editar/3, React Router captura el valor 3 y lo pone disponible para el componente a través del hook useParams.

Paso 5Crear la página de formulario PersonaFormPage.jsx

Esta página sirve para dos propósitos en uno: crear una persona nueva (cuando no hay id en la URL) y editar una existente (cuando sí hay id). El hook useParams determina cuál de los dos casos aplica.

src/pages/PersonaFormPage.jsx — archivo nuevo

Este componente demuestra un patrón importante: una sola página, dos modos de operación. La lógica de decisión es simple: si id existe en la URL, se carga la persona y se actualiza; si no existe, se crea una nueva. El formulario visual PersonaForm es el mismo en ambos casos.

💡 useEffect con [id] como dependencia: El arreglo [id] al final del useEffect significa "ejecuta este efecto cuando el componente monte Y cada vez que id cambie". Esto es importante porque si el usuario navega de /editar/3 a /editar/5 sin desmontar el componente, el formulario se recarga con los datos correctos.
