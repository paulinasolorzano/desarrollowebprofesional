2 Conceptos clave: React Router DOM
🗺️ ¿Qué es React Router DOM y para qué sirve?

React por sí solo no sabe nada de URLs. Cuando el usuario escribe /personas/nueva en la barra del navegador, React no tiene forma de saber qué mostrar. React Router DOM es la biblioteca que resuelve eso: conecta cada URL con el componente que debe mostrarse.

Lo instalas aparte con npm install react-router-dom porque no viene incluido en React.

Analogía: React es el edificio con todas las habitaciones (componentes). React Router es el sistema de señalización que le dice al visitante a qué habitación ir dependiendo de la planta que pidió (la URL).
🧱 Los 4 elementos que usarás en esta práctica
Elemento¿Dónde se pone?¿Qué hace?
BrowserRoutermain.jsxActiva el sistema de rutas en toda la app. Envuelve todo.
Routes + RouteApp.jsxDefine las reglas: URL X → muestra componente Y.
LinkCualquier componenteEnlace que navega sin recargar la página. Reemplaza a <a href>.
useNavigateDentro de funcionesNavega desde el código. Ej: después de guardar el formulario, ir al listado.
useParamsComponente de ediciónLee el :id de la URL. Ej: en /personas/editar/3 extrae el 3.
¿Por qué Link y no <a href>? Un <a href> recarga toda la página — React pierde todo su estado. Link cambia la URL sin recargar, manteniendo la aplicación viva y el estado intacto.
📂 pages/ vs components/ — ¿cuál es la diferencia?

En esta práctica crearemos una carpeta nueva llamada pages/. La diferencia con components/ es de responsabilidad:

Carpeta¿Qué contiene?Ejemplo
src/pages/Pantallas completas. Cada una corresponde a una URL.PersonasPage.jsx → /personas
src/components/Piezas reutilizables. No saben en qué URL están.PersonaForm.jsx, Navbar.jsx

Las páginas usan componentes. Los componentes no saben qué página los está usando. Esa separación hace el proyecto más fácil de mantener conforme crece.

BrowserRouter debe envolver a toda la aplicación para que el sistema de rutas funcione. Se pone en main.jsx porque es el punto de entrada — así toda la jerarquía de componentes tiene acceso al sistema de navegación desde el inicio.

¿Por qué BrowserRouter va en main.jsx y no en App.jsx? Porque BrowserRouter necesita envolver a App.jsx. Si lo pusieras dentro de App.jsx, estaría intentando envolverse a sí mismo. En main.jsx queda fuera de App y lo envuelve correctamente.

Paso 5Crear la página de formulario PersonaFormPage.jsx

Esta es la pantalla que aparece tanto en /personas/nueva como en /personas/editar/:id. Un mismo componente maneja los dos casos: si hay id en la URL carga los datos de esa persona; si no hay id, muestra el formulario vacío para crear.

src/pages/PersonaFormPage.jsx — archivo nuevo
💡 Un componente, dos modos: useParams devuelve { id: '3' } cuando la URL es /personas/editar/3, y devuelve { id: undefined } cuando la URL es /personas/nueva. Con esa sola diferencia el componente sabe si debe crear o actualizar.
useEffect con [id] como dependencia: El arreglo [id] al final del useEffect significa "ejecuta este código cuando el componente cargue Y también cada vez que cambie el id". Esto garantiza que si el usuario navega de /editar/3 a /editar/5, el formulario se recarga con los datos correctos.
