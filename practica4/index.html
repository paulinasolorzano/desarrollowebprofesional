2 Conceptos clave que debes conocer

Antes de escribir código, es importante entender qué rol juega cada tecnología en el frontend.

⚛️ ¿Qué es React?

React es una biblioteca de JavaScript desarrollada por Meta (Facebook) para construir interfaces de usuario. Su idea central es que la interfaz se divide en componentes: piezas reutilizables que encapsulan su propio HTML, lógica y estado.

Cuando los datos cambian, React actualiza automáticamente solo las partes de la pantalla que necesitan cambiar, sin recargar toda la página. Esto hace las aplicaciones mucho más rápidas y fluidas.

Analogía: Imagina que tu interfaz es un periódico. La forma tradicional sería reimprimir todo el periódico cada vez que cambia una noticia. React es como tener cada sección (portada, deportes, cultura) como una pieza independiente: si cambia deportes, solo se reimprime esa sección.
⚡ ¿Qué es Vite?

Vite es una herramienta de construcción (bundler) para proyectos web modernos. Su trabajo es tomar todos tus archivos de código fuente (componentes .jsx, estilos, imágenes) y transformarlos en archivos que el navegador pueda entender y ejecutar.

Vite es significativamente más rápido que herramientas anteriores como Create React App porque usa un servidor de desarrollo inteligente que solo compila lo que se necesita en el momento, no todo el proyecto de una vez.

Analogía: Vite es como un chef que prepara los platillos bajo pedido en lugar de cocinar todo el menú desde el inicio. Solo procesa lo que estás mirando en ese momento, lo cual es mucho más eficiente.
🧩 ¿Qué es un componente en React?

Un componente es una función de JavaScript que devuelve HTML (escrito en una sintaxis especial llamada JSX). Los componentes son la unidad básica de construcción en React: puedes combinarlos, reutilizarlos y anidarlos como bloques de construcción.

Cada componente puede tener su propio estado (datos que pueden cambiar) y props (datos que recibe de su componente padre).

Analogía: Los componentes son como los controles de un formulario de papel: tienes el componente "campo de texto", el "botón", el "tabla". Cada uno hace una cosa, puede usarse muchas veces, y se combinan para formar la interfaz completa.
🎣 ¿Qué son los Hooks de React?

Los Hooks son funciones especiales de React que permiten a los componentes recordar información (estado) y ejecutar efectos secundarios (como llamadas a la API). Los más importantes para esta práctica son:

useState — guarda y actualiza datos dentro de un componente. Cuando el estado cambia, React vuelve a renderizar el componente con los nuevos datos.

useEffect — ejecuta código cuando el componente aparece en pantalla (o cuando algo cambia). Se usa para cargar datos desde la API al momento de montar el componente.

Analogía: useState es la memoria del componente (recuerda cuántas personas hay en la lista). useEffect es la acción que se dispara al abrir la página (ve a buscar las personas a la API).
📡 ¿Qué es axios y por qué lo usamos?

Axios es una biblioteca de JavaScript que facilita hacer peticiones HTTP desde el navegador. Permite consumir nuestra API REST (los endpoints que creamos en P03) de forma sencilla y con manejo de errores integrado.

Aunque JavaScript tiene el método nativo fetch, axios ofrece ventajas como: transformación automática de JSON, interceptores de peticiones (útiles para autenticación en prácticas futuras), y una sintaxis más limpia.

Analogía: Si el backend es un restaurante y la API es el menú, axios es el mesero: tú le dices qué quieres, él va a buscarlo y te lo trae correctamente presentado.
🎨 ¿Por qué Bootstrap en React?

Bootstrap es un conjunto de estilos CSS predefinidos que permite construir interfaces profesionales y responsivas sin escribir CSS desde cero. En React lo usaremos a través de clases CSS de Bootstrap aplicadas a nuestros elementos JSX.

Lo instalamos vía npm y lo importamos una vez en el archivo principal. A partir de ahí, todas las clases de Bootstrap (btn, table, container, etc.) están disponibles en todos los componentes.

Nota de organización: Colocamos las llamadas a la API en una carpeta separada (src/api/) desde el inicio. Esto sigue buenas prácticas: cuando el proyecto crezca, todas las funciones que hablan con el servidor estarán en un solo lugar fácil de encontrar y modificar.

Paso 3 Configurar el proxy en Vite para evitar errores CORS

Cuando React (en el puerto 5173) intenta hacer peticiones al backend (en el puerto 3000), el navegador puede bloquear la solicitud por la política CORS. La solución más limpia durante el desarrollo es configurar un proxy en Vite: todas las peticiones a /api serán redirigidas automáticamente a nuestro backend.

vite.config.js — reemplazar contenido completo

Con esta configuración, cuando desde React haces una petición a /api/personas, Vite la redirige internamente a http://localhost:3000/api/personas sin que el navegador lo vea como un cruce de dominios.

💡 Buena práctica: Esta configuración de proxy solo aplica durante el desarrollo. En producción, el frontend y el backend generalmente se sirven desde el mismo dominio o se configura CORS correctamente en el servidor. Por ahora el proxy es la solución más práctica.
Paso 4 Crear el módulo de llamadas a la API

Antes de crear los componentes visuales, vamos a separar la lógica de comunicación con el servidor en su propio archivo. Crea la carpeta src/api/ y dentro el archivo personas.api.js:

src/api/personas.api.js — archivo nuevo

Este módulo exporta funciones que encapsulan cada llamada HTTP. Los componentes solo necesitan llamar a getPersonas() sin preocuparse de cómo funciona axios internamente.

💡 Patrón de separación: Este patrón (separar la lógica de red en módulos aparte) es estándar en proyectos React profesionales. Si en el futuro cambia la URL base de la API o la librería HTTP, solo modificas este archivo, no cada componente que usa los datos.

Paso 6 Crear el componente PersonasLista

Este es el componente central de la práctica. Carga la lista de personas desde la API y la muestra en una tabla Bootstrap. Crea el archivo PersonasLista.jsx dentro de src/components/:

src/components/PersonasLista.jsx — archivo nuevo

Analiza lo que hace este componente:

  • useState([]) — declara el estado personas como un arreglo vacío al inicio.
  • useState(true) — declara cargando como verdadero (mostrará el spinner al inicio).
  • useEffect — se ejecuta una sola vez cuando el componente aparece en pantalla y llama a la API.
  • La función cargarPersonas llama a getPersonas() del módulo que creamos, guarda los datos en el estado y oculta el spinner.
  • Si hay un error de red, lo muestra al usuario en lugar de fallar silenciosamente.

Paso 8 Limpiar los archivos generados por Vite

Vite genera algunos archivos de demostración que ya no necesitamos. Elimina o vacía los siguientes:

  • Elimina el contenido de src/App.css (o borra el archivo si App.jsx no lo importa ya).
  • Elimina el archivo src/assets/react.svg — es el logo de demostración de Vite.
  • Deja index.css con solo el reset básico si lo deseas, o vacíalo.
¿Por qué limpiar? Los archivos de demo de Vite pueden generar estilos que interfieren con Bootstrap. Eliminarlos desde ahora evita problemas de CSS más adelante cuando agreguemos más componentes.

7 Preguntas de reflexión
  1. ¿Por qué usamos useEffect con un arreglo vacío [] como segundo argumento? ¿Qué pasaría si lo omites?
  2. ¿Cuál es la diferencia entre el estado cargando y el estado personas? ¿Por qué necesitamos ambos?
  3. ¿Por qué separamos las llamadas a la API en un archivo aparte en lugar de escribirlas directamente en el componente?
  4. Si quisieras mostrar también el número total de personas (incluyendo las inactivas), ¿cómo lo harías sin hacer una segunda petición a la API?
  5. ¿Qué ventaja tiene el proxy de Vite sobre habilitar CORS directamente en el backend durante el desarrollo?
