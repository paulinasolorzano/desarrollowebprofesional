2 Conceptos clave que debes conocer
⚛️ ¿Qué es React?

React es una biblioteca de JavaScript para construir interfaces de usuario. Su idea central es dividir la interfaz en componentes: piezas reutilizables que encapsulan su propio HTML, lógica y estado. Cuando los datos cambian, React actualiza automáticamente solo las partes de la pantalla que lo necesitan, sin recargar la página completa.

Analogía: Imagina que tu interfaz es un periódico. La forma tradicional sería reimprimir todo el periódico cada vez que cambia una noticia. React es como tener cada sección (portada, deportes, cultura) como una pieza independiente: si cambia deportes, solo se reimprime esa sección.
⚡ ¿Qué es Vite?

Vite es la herramienta que convierte tu código React en algo que el navegador puede ejecutar. Cuando escribes un componente en un archivo .jsx, el navegador no lo entiende directamente — necesita un proceso de transformación. Ese es el trabajo de Vite.

Además de transformar el código, Vite ofrece un servidor de desarrollo en vivo: cada vez que guardas un archivo, la página se actualiza automáticamente en el navegador sin que tengas que recargarla.

Analogía: Vite es como el horno en una panadería. Tú escribes la receta y pones los ingredientes (código fuente). El horno los transforma en algo que se puede consumir (archivos que el navegador entiende). Sin el horno, la receta sola no sirve.
🧩 ¿Qué es un componente y por qué creamos la carpeta components/?

Un componente es una función de JavaScript que devuelve JSX (una mezcla de JavaScript y HTML). Los componentes son la unidad básica de React: todo lo que ves en la pantalla es un componente.

Creamos la carpeta src/components/ para organizar el proyecto de la misma manera que el backend usa controllers/ y routes/. No es un requisito técnico de React, pero sí una convención profesional que separa responsabilidades:

Backend (P02–P03)Frontend (P04)¿Para qué?
controllers/components/Lógica y presentación por módulo
routes/api/Define cómo llega/sale la información
server.jsApp.jsxPunto de entrada que ensambla todo

Así como en el backend no escribimos todo en server.js, en React no escribiremos todo en App.jsx. Cada componente tiene su propio archivo con una responsabilidad clara.

🎣 ¿Qué son los Hooks de React?

Los Hooks son funciones especiales de React que permiten a los componentes recordar información (estado) y ejecutar acciones automáticas (efectos). Los dos más importantes para esta práctica:

useState — guarda y actualiza datos dentro de un componente. Cuando el estado cambia, React vuelve a pintar el componente con los nuevos datos.

useEffect — ejecuta código cuando el componente aparece en pantalla. Se usa para cargar datos desde la API al momento en que el usuario abre la página.

Analogía: useState es la memoria del componente (recuerda cuántas personas hay en la lista). useEffect es la acción que se dispara al abrir la página (ve a buscar las personas a la API automáticamente).
3 ¿Cuándo uso <> y cuándo <View>?

Esta es una pregunta muy común al empezar con React. La respuesta depende de en qué plataforma estás trabajando.

🌐 <></> — Fragmento de React (para aplicaciones web)

En React para la web, un componente debe devolver un solo elemento raíz. Pero muchas veces quieres devolver varios elementos sin agregar un <div> innecesario que ensucie el HTML.

El fragmento vacío <></> es la solución: agrupa varios elementos sin crear ningún nodo real en el HTML del navegador. También puedes escribirlo como <React.Fragment></React.Fragment>, pero la forma corta es la más usada.

¿Cuándo lo usas? Siempre que necesites devolver dos o más elementos en un componente web sin añadir un contenedor real. En este proyecto lo usarás en App.jsx para envolver <Navbar /> y <PersonasLista /> juntos.
📱 <View></View> — Solo existe en React Native (para aplicaciones móviles)

<View> no existe en React para web. Es un componente exclusivo de React Native, que es una versión diferente de React pensada para construir aplicaciones móviles (iOS y Android).

En React Native no existen etiquetas HTML como <div>, <p> o <table>. En su lugar se usan componentes nativos como <View> (equivalente a <div>), <Text> (equivalente a <p>) y <ScrollView>.

¿Cuándo lo usas? Solo cuando estés construyendo una aplicación móvil con React Native (como la app GuayabaApp del proyecto de árbol de UTM). Nunca en un proyecto web como este.
Elemento Plataforma ¿Para qué sirve? ¿Se renderiza en el DOM?
<></> React Web ✅ Agrupa elementos sin contenedor extra No — desaparece en el HTML final
<div></div> React Web ✅ Contenedor genérico con bloque visual Sí — aparece en el HTML como <div>
<View></View> React Native 📱 Contenedor para móvil (como <div> pero nativo) No aplica — se convierte en vista nativa iOS/Android
Regla práctica para este proyecto: Usa <></> cuando necesites agrupar sin <div>. Usa <div> cuando sí necesites el contenedor (para estilos, layout, etc.). <View> nunca lo usarás aquí.
4 fetch vs axios: lo que hacías antes y lo que harás ahora

Es posible que hayas usado fetch en alguna materia anterior para pedir datos a un servidor. En este proyecto usaremos axios. Aquí se muestra exactamente la misma operación escrita de las dos formas para que identifiques las diferencias:

❌ Con fetch (lo que hacías antes)
✅ Con axios (lo que harás ahora)
Caso 2 — Crear una persona nueva (POST con cuerpo JSON)
❌ Con fetch
✅ Con axios
¿Por qué axios es mejor para este proyecto?
Característicafetch (nativo)axios (librería)
Transformación de JSONManual: debes llamar .json() siempreAutomática: ya viene como objeto JS
Enviar JSON en POST/PUTDebes serializar y agregar headers manualmenteAutomático: pasas el objeto y listo
Errores HTTP (404, 500)No lanza error — debes revisar res.okLanza error automáticamente con el código
Interceptores (JWT en P06)No tiene — necesitas código extraTiene interceptores: agrega el token en un solo lugar
Código resultanteMás largo y repetitivoMás corto y legible
💡 Nota importante: axios no viene con el navegador — hay que instalarlo con npm install axios. fetch sí viene incluido en todos los navegadores modernos sin instalar nada. Usamos axios porque en las prácticas P06–P07 agregaremos autenticación con JWT, y los interceptores de axios harán esa parte mucho más sencilla.
5 Flujo de datos: cómo se comunican frontend y backend

El siguiente diagrama muestra paso a paso qué ocurre desde que el usuario abre la página hasta que ve los datos en la tabla. Cada número corresponde a un paso del recorrido de la información.

📡 Flujo completo: GET /api/personas
Descripción paso a paso
#¿Qué ocurre?¿En qué archivo?
①El usuario abre localhost:5173. Vite sirve el HTML y carga React.index.html + main.jsx
②React monta el componente PersonasLista. useEffect se dispara automáticamente porque el componente acaba de aparecer en pantalla.PersonasLista.jsx
③Se llama a getPersonas(), que usa axios para enviar una petición HTTP GET a /api/personas. El proxy de Vite la redirige a localhost:3000.personas.api.js
④Express recibe la petición en el servidor backend. La compara con las rutas registradas y encuentra que GET /api/personas corresponde a la función getAll.server.js → personas.routes.js
⑤El controlador ejecuta la función getAll usando async/await para consultar la base de datos.personas.controller.js
⑥MySQL ejecuta la consulta SELECT * FROM personas WHERE activo = 1 y devuelve las filas encontradas al controlador.Base de datos MySQL
⑦El controlador recibe las filas y responde con res.json(rows). Express envía de vuelta al frontend un arreglo JSON con código HTTP 200.personas.controller.js
⑧axios recibe la respuesta. La función setPersonas(datos) actualiza el estado del componente. React detecta el cambio y vuelve a renderizar la tabla con los datos reales. El usuario los ve.PersonasLista.jsx
Resumen del flujo: Usuario abre página → React monta componente → axios pide datos → Express los busca en MySQL → MySQL devuelve filas → Express responde JSON → axios lo recibe → React pinta la tabla.

💡 ¿Por qué creamos components/ y api/? Siguiendo el mismo principio que el backend: separar responsabilidades. api/ contiene solo las funciones que hablan con el servidor. components/ contiene solo la presentación visual. App.jsx los ensambla. Así, si mañana cambia la URL de la API, solo modificas api/personas.api.js, no cada componente que usa los datos.

Paso 3Entender y configurar vite.config.js

¿Qué es vite.config.js? Es el archivo de configuración de Vite. Controla cómo funciona el servidor de desarrollo, cómo se compila el proyecto y, en este caso, cómo se redirigen las peticiones HTTP durante el desarrollo.

Cuando Vite crea el proyecto, ya genera un vite.config.js básico. Nosotros necesitamos agregar la sección server.proxy para resolver el siguiente problema:

⚠️ El problema de CORS: Tu frontend corre en el puerto 5173 y tu backend en el puerto 3000. El navegador detecta esto como dos "orígenes" diferentes y bloquea las peticiones por seguridad. Esto se llama Cross-Origin Resource Sharing (CORS). Si no lo resuelves, axios recibirá un error de red aunque el backend esté funcionando perfectamente.

¿Qué hace el proxy? Le dice a Vite: "Si el frontend pide algo a /api/…, reenvía esa petición a http://localhost:3000 por dentro, sin que el navegador lo vea como un cruce de dominios."

vite.config.js — reemplazar el contenido completo
¿Qué significa cada línea?
Línea / propiedad¿Qué hace?¿Debes cambiarla?
plugins: [react()]Activa el soporte de React y JSX en Vite. Sin esto no reconoce .jsx.No, dejarla igual
server: { proxy: { ... } }Configura el servidor de desarrollo para redirigir rutas.No, es el contenedor
'/api'Toda petición que empiece con /api será redirigida.Solo si cambias el prefijo de tu API

¿Cuándo modificarías target? Si tu backend no corre en el puerto 3000 (por ejemplo, corre en 4000 porque tienes otro servicio en 3000), cambiarías la línea a target: 'http://localhost:4000'. El resto no cambia.
💡 Solo aplica en desarrollo: Esta configuración de proxy solo funciona con npm run dev. Cuando hagas el build final para producción (npm run build), el proxy desaparece. En producción el frontend y backend se configuran con un servidor real (nginx, etc.).

src/components/PersonasLista.jsx — archivo nuevo
