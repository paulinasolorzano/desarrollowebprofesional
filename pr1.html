1 ¿Dónde estamos en el proyecto?

En la práctica anterior diseñamos y creamos la base de datos del sistema. Ya tenemos las tablas personas, usuarios, proyectos y tareas con sus relaciones en MySQL.

Ahora necesitamos construir el backend: el servidor que recibirá peticiones desde el navegador, consultará la base de datos y devolverá respuestas en formato JSON. Este servidor es el puente entre la interfaz visual (que haremos después en React) y los datos almacenados en MySQL.

Para esto usaremos Node.js como entorno de ejecución y Express como framework para manejar las rutas y peticiones HTTP.

Recuerda: El backend no tiene interfaz visual. Todo se prueba mediante peticiones HTTP usando herramientas como Thunder Client (extensión de VS Code) o Postman.

4 Estructura del proyecto

Antes de escribir código, crea esta estructura de carpetas. Una buena organización desde el inicio facilita el crecimiento del proyecto.

/backend
  ├── server.js        punto de entrada del servidor
  ├── db.js           conexión a MySQL (pool)
  ├── .env            variables de entorno (NO subir a Git)
  ├── .env.example    plantilla pública sin valores reales
  ├── .gitignore      archivos que Git debe ignorar
  ├── package.json    configuración del proyecto npm
  ├── /routes        definición de rutas por módulo
  ├── /controllers   lógica de negocio por módulo
  ├── /middlewares   autenticación, permisos, errores
  └── /config       configuraciones generales
Patrón MVC básico: Separar las rutas (qué URL atiende qué), los controladores (qué hace cuando llega esa petición) y los modelos o acceso a datos (cómo consulta la base de datos) es una buena práctica que facilita el mantenimiento del código a largo plazo.
5 Desarrollo paso a paso
Paso 1 Inicializar el proyecto Node.js

Abre la terminal en la carpeta /backend y ejecuta los siguientes comandos. El flag -y acepta todos los valores por defecto del package.json.

# Inicializar el proyecto npm init -y
# Instalar dependencias principales npm install express mysql2 dotenv cors
# Instalar nodemon como dependencia de desarrollo # (reinicia el servidor automáticamente al guardar cambios) npm install --save-dev nodemon
¿Qué instalamos? express — framework web. mysql2 — conector para MySQL con soporte de promesas. dotenv — carga variables desde el archivo .env. cors — permite que el frontend (React) se comunique con este servidor. nodemon — recarga automática en desarrollo.
Paso 2 Configurar package.json

Agrega los scripts de inicio en el package.json para poder ejecutar el servidor fácilmente.

📄 package.json
{ "name": "sistema-admin-backend", "version": "1.0.0", "type": "module", // habilita import/export de ES Modules "scripts": { "start": "node server.js", // producción "dev": "nodemon server.js"  // desarrollo }, }
Básico vs profesional: Usar "type": "module" nos permite escribir import en lugar de require(). Es la sintaxis moderna de JavaScript. En este curso usaremos import/export desde el inicio.
Paso 3 Crear el archivo .env

Este archivo contiene los datos sensibles de conexión. Nunca debe subirse a GitHub. Crea también un archivo .env.example con las mismas claves pero sin valores reales, para que otros desarrolladores sepan qué necesitan configurar.

📄 .env
# Servidor PORT=3000
# Base de datos MySQL DB_HOST=localhost DB_USER=root DB_PASS=tu_contraseña_aqui DB_NAME=sistema_admin
# JWT (se usará en la Práctica 6) JWT_SECRET=clave_secreta_muy_larga_y_segura
📄 .env.example
PORT= DB_HOST= DB_USER= DB_PASS= DB_NAME= JWT_SECRET=
📄 .gitignore
# Dependencias node_modules/
# Variables de entorno (¡NUNCA subir a Git!) .env
Seguridad crítica: Si subes el archivo .env a GitHub, cualquier persona puede ver tu contraseña de base de datos y la clave secreta del JWT. Agrega .env al .gitignore antes de tu primer commit.
Paso 4 Crear db.js — conexión a MySQL

Este archivo crea y exporta un pool de conexiones. Un pool mantiene varias conexiones abiertas y las reutiliza, lo cual es mucho más eficiente que abrir y cerrar una conexión nueva en cada petición.

📄 db.js
import mysql from 'mysql2/promise'; import dotenv from 'dotenv';
dotenv.config();
const pool = mysql.createPool({ host: process.env.DB_HOST, user: process.env.DB_USER, password: process.env.DB_PASS, database: process.env.DB_NAME, waitForConnections: true, connectionLimit: 10, // máximo 10 conexiones simultáneas queueLimit: 0 });
export default pool;
¿Por qué mysql2/promise? Esta versión del conector devuelve promesas de forma nativa, lo que nos permite usar async/await en los controladores de forma limpia, sin callbacks.
Paso 5 Crear server.js — servidor Express

Este es el punto de entrada de toda la aplicación. Configura Express, habilita CORS y JSON, define las rutas base y arranca el servidor en el puerto indicado en .env.

📄 server.js
import express from 'express'; import cors from 'cors'; import dotenv from 'dotenv';
dotenv.config();
const app = express();
// Middlewares globales app.use(cors());               // permite peticiones desde el frontend app.use(express.json());        // parsea el body de las peticiones como JSON
// Ruta de diagnóstico (health check) app.get('/api/health', (req, res) => { res.json({ status: 'ok', mensaje: 'Servidor funcionando correctamente', timestamp: new Date().toISOString() }); });
// Aquí se agregarán las rutas de cada módulo en prácticas posteriores // import personasRoutes from './routes/personas.routes.js'; // app.use('/api/personas', personasRoutes);
// Arrancar el servidor const PORT = process.env.PORT || 3000; app.listen(PORT, () => { console.log(`Servidor corriendo en http://localhost:${PORT}`); });
Paso 6 Verificar la conexión a MySQL

Agrega esta verificación al final de server.js para confirmar que la conexión a la base de datos es exitosa al arrancar el servidor.

📄 server.js — agregar al final
import pool from './db.js';
// Verificar conexión a la base de datos al iniciar const verificarConexion = async () => { try { const conn = await pool.getConnection(); console.log('✅ Conexión a MySQL exitosa'); conn.release(); // devolver la conexión al pool } catch (error) { console.error('❌ Error al conectar a MySQL:', error.message); } };
verificarConexion();
Paso 7 Ejecutar y probar el servidor

Ejecuta el servidor en modo desarrollo con nodemon y prueba el endpoint de diagnóstico con Thunder Client.

# Ejecutar en modo desarrollo (se reinicia automáticamente) npm run dev

En la terminal deberías ver:

Servidor corriendo en http://localhost:3000 ✅ Conexión a MySQL exitosa

Abre Thunder Client en VS Code y realiza una petición GET a:

GET  http://localhost:3000/api/health

Respuesta esperada:

{ "status": "ok", "mensaje": "Servidor funcionando correctamente", "timestamp": "2025-03-15T10:30:00.000Z" }
Código 200 OK: Si Thunder Client muestra código 200 junto con ese JSON, el servidor está funcionando correctamente y está conectado a la base de datos.
