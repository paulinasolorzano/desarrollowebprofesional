1 ¿Dónde estamos en el proyecto?

En la práctica anterior creamos la base de datos con sus cuatro tablas: personas, usuarios, proyectos y tareas. Ya tenemos los datos guardados en MySQL.

Ahora necesitamos construir el backend: el servidor que recibirá peticiones, consultará la base de datos y devolverá respuestas. Sin el backend, la base de datos no puede comunicarse con ninguna aplicación.

El sistema completo que vamos a construir a lo largo del curso se divide en tres partes. En esta práctica trabajamos en la parte del servidor:

¿Y React? ¿Cuándo lo usamos?

React es el frontend, es decir, la interfaz visual que verá el usuario en el navegador. Todavía no lo usamos. Primero necesitamos tener el backend funcionando correctamente. React se introduce en la Práctica 4, una vez que las APIs estén listas y probadas. Por ahora, todo el trabajo es del lado del servidor.

2 Conceptos clave que debes conocer

Antes de escribir código, es importante entender qué hace cada tecnología y por qué la usamos.

⚙️ ¿Qué es Node.js?

Node.js es un entorno de ejecución que permite correr código JavaScript fuera del navegador, directamente en el servidor o en tu computadora. Antes de Node.js, JavaScript solo podía ejecutarse dentro de un navegador web.

Gracias a Node.js podemos escribir el servidor de nuestro sistema administrativo usando el mismo lenguaje (JavaScript) tanto en el frontend como en el backend.

Analogía: Piensa en JavaScript como un idioma. Antes solo podías hablarlo dentro del navegador (como hablar solo en tu habitación). Node.js te permite hablar ese mismo idioma en cualquier lugar: en el servidor, en la terminal, en scripts automatizados.
🚂 ¿Qué es Express?

Express es un framework (conjunto de herramientas) para Node.js que facilita la creación de servidores web. Node.js solo te da las herramientas básicas; Express las organiza y simplifica para que puedas crear rutas, manejar peticiones y respuestas de forma mucho más sencilla.

Analogía: Node.js es como tener todos los materiales de construcción sueltos (ladrillos, cemento, varillas). Express es como tener un plano y herramientas organizadas para construir más rápido y con orden.
🌐 ¿Qué es un servidor HTTP y una API REST?

Un servidor HTTP es un programa que está "escuchando" en un puerto de tu computadora esperando peticiones. Cuando alguien hace una petición (por ejemplo, abrir una página web o consultar datos), el servidor responde con información.

Una API REST (Application Programming Interface) es una forma estandarizada de comunicarse con un servidor. En lugar de páginas HTML, devuelve datos en formato JSON que cualquier aplicación puede interpretar, ya sea una app móvil, un sitio web o un sistema de escritorio.

Analogía: El servidor es como un restaurante. La API REST es el menú con las opciones disponibles. Tú (el cliente) haces un pedido (petición HTTP), el mesero lo lleva a cocina (servidor), y recibes tu platillo (respuesta JSON).
📡 ¿Qué es un endpoint y los verbos HTTP?

Un endpoint es una URL específica de tu API que realiza una acción concreta. Cada endpoint se combina con un verbo HTTP que indica qué tipo de acción se quiere realizar:

Verbo Acción Ejemplo
GETObtener datosGET /api/personas → lista todas las personas
POSTCrear un registroPOST /api/personas → crea una nueva persona
PUTActualizar un registroPUT /api/personas/5 → actualiza la persona con id 5
DELETEEliminar un registroDELETE /api/personas/5 → elimina la persona con id 5
🔒 ¿Qué son las variables de entorno?

Las variables de entorno son datos sensibles (contraseñas, claves secretas, nombres de servidores) que no deben estar escritos directamente en el código. Se guardan en un archivo separado llamado .env que nunca se sube a internet.

Imagina que tu código es un libro que compartes con otros. Si escribes tu contraseña de MySQL dentro del código, cualquier persona que vea ese código tendrá tu contraseña. Con las variables de entorno, el libro solo dice "aquí va la contraseña" pero el valor real está en un cuaderno privado tuyo.

Analogía: El archivo .env es como tu cartera: contiene información personal que no muestras a todo el mundo. El archivo .env.example es como un formulario vacío que le das a alguien para que sepa qué datos necesita poner en su propia cartera.
🔗 ¿Qué es un pool de conexiones?

Cada vez que el servidor necesita consultar la base de datos, necesita abrir una conexión a MySQL. Abrir y cerrar una conexión nueva en cada petición es lento y consume muchos recursos.

Un pool de conexiones mantiene un grupo de conexiones abiertas y listas para usar. Cuando llega una petición, toma una conexión disponible del pool, la usa, y la devuelve al pool para que otra petición pueda usarla.

Analogía: Imagina un estacionamiento con 10 lugares (el pool). En lugar de construir un lugar nuevo cada vez que llega un carro (abrir conexión), simplemente asignas un lugar disponible y cuando el carro se va, el lugar queda libre para otro.
🔄 ¿Qué es async/await?

Cuando Node.js consulta la base de datos, esa operación tarda un tiempo. async/await es una forma de decirle a JavaScript: "espera a que esta operación termine antes de continuar", sin bloquear todo el servidor.

La palabra async marca una función como asíncrona. La palabra await pausa la ejecución dentro de esa función hasta que la promesa se resuelva. Si algo falla, se captura el error con try/catch.

Analogía: Es como pedir comida a domicilio. No te quedas parado en la puerta esperando (bloqueado). Sigues haciendo tus cosas y cuando llega el repartidor (la respuesta), atiendes la puerta (continúas la ejecución).

4 Estructura del proyecto

Crea la siguiente estructura de carpetas antes de escribir cualquier código. Esta organización sigue el patrón MVC (Modelo-Vista-Controlador), que separa responsabilidades y facilita el mantenimiento del proyecto.

/backend
  ├── server.js        ← punto de entrada del servidor
  ├── db.js           ← conexión a MySQL (pool)
  ├── .env            ← variables de entorno (NO subir a Git)
  ├── .env.example    ← plantilla sin valores reales
  ├── .gitignore      ← archivos que Git debe ignorar
  ├── package.json    ← configuración del proyecto npm
  ├── /routes        ← definición de rutas por módulo
  ├── /controllers   ← lógica de negocio por módulo
  ├── /middlewares   ← autenticación, permisos, errores
  └── /config       ← configuraciones generales
Por ahora solo crearás los archivos server.js, db.js, .env, .env.example y .gitignore. Las carpetas /routes, /controllers y /middlewares se irán llenando en prácticas posteriores.
5 Desarrollo paso a paso
Paso 1Inicializar el proyecto e instalar dependencias

Abre la terminal en la carpeta /backend y ejecuta los siguientes comandos. El flag -y en npm init acepta todos los valores por defecto automáticamente.

Terminal

Una vez instaladas, estas son las dependencias y para qué sirve cada una:

PaqueteTipo¿Para qué sirve?
expressProducciónFramework web para crear rutas y manejar peticiones HTTP
mysql2ProducciónConector para MySQL con soporte de promesas (async/await)
dotenvProducciónCarga las variables del archivo .env en el proyecto
corsProducciónPermite que el frontend (React) pueda hacer peticiones al servidor
nodemonDesarrolloReinicia el servidor automáticamente cada vez que guardas un archivo
Dependencias de desarrollo vs producción: nodemon se instala con --save-dev porque solo se usa mientras desarrollamos, no en el servidor final. Las otras dependencias sí se necesitan cuando el sistema esté en producción.
Paso 2Configurar package.json

Abre el archivo package.json que se generó y agrégale los scripts de inicio y la propiedad "type": "module" para poder usar la sintaxis moderna de JavaScript (import en lugar de require).

📄 package.json
Básico vs profesional: "type": "module" activa los módulos ES6 nativos de JavaScript. Esto nos permite usar import/export en lugar del antiguo require(). Es la forma moderna y la que usaremos en todo el proyecto.
Paso 3Crear los archivos de configuración

Crea los tres archivos siguientes. El .env contiene los valores reales de tu entorno. El .env.example es una plantilla vacía que sí se puede compartir. El .gitignore protege el .env de ser subido accidentalmente a Git.

📄 .env — tus datos reales (nunca compartir)
📄 .env.example — plantilla sin valores
📄 .gitignore
Seguridad crítica: Si subes el archivo .env a GitHub, cualquier persona en internet puede ver tu contraseña de MySQL y la clave secreta del JWT. Siempre agrega .env al .gitignore antes de hacer tu primer commit.
Paso 4Crear db.js — la conexión a MySQL

Este archivo crea un pool de conexiones a MySQL y lo exporta para que cualquier parte del proyecto pueda usarlo. Usa mysql2/promise para poder trabajar con async/await.

📄 db.js
¿Por qué connectionLimit: 10? Significa que como máximo habrá 10 conexiones abiertas al mismo tiempo. Si llegan más peticiones simultáneas, esperarán a que se libere una. Esto evita saturar la base de datos.
Paso 5Crear server.js — el servidor Express

Este es el corazón del backend. Aquí se configura Express, se habilitan los middlewares globales, se define la primera ruta de prueba y se arranca el servidor en el puerto definido en el .env.

📄 server.js
¿Qué es un middleware? Es una función que se ejecuta en medio de cada petición, antes de llegar a la ruta final. cors() y express.json() son middlewares globales que procesan todas las peticiones. En prácticas posteriores crearemos nuestros propios middlewares para autenticación y permisos.
Paso 6Ejecutar y probar el servidor

Ejecuta el servidor en modo desarrollo. El comando npm run dev usa nodemon, que reiniciará el servidor automáticamente cada vez que modifiques un archivo.

Terminal — ejecutar

Si todo está correcto, verás estos mensajes en la terminal:

Terminal — salida esperada

Abre Thunder Client en VS Code y crea una petición GET a la siguiente URL:

Thunder Client — petición GET

La respuesta esperada con código 200 OK es:

Thunder Client — respuesta JSON
¿Por qué Thunder Client y no el navegador? El navegador solo puede hacer peticiones GET fácilmente. Thunder Client permite probar todos los verbos HTTP (GET, POST, PUT, DELETE) con cualquier cuerpo de datos, lo cual es indispensable para desarrollar y probar APIs REST.
