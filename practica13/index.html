1 El sistema completo — ¿qué construiste?

A lo largo de 13 prácticas construiste un Sistema Administrativo Web profesional de cero. No es un ejercicio de práctica — es una aplicación real con todas las capas que tiene un sistema en producción: base de datos relacional, API REST segura, interfaz de usuario reactiva, autenticación con JWT, cifrado de contraseñas, control de acceso por roles, validación de entradas, auditoría y protección ante los ataques más comunes.

En P13 cierras el proyecto: agregas un dashboard con estadísticas reales, escribes la documentación, pruebas el sistema completo de forma integral y lo preparas para entrega.

3 README profesional

El README.md es la documentación principal del proyecto. Cualquier desarrollador que reciba el ZIP debe poder levantar el sistema en su máquina sin preguntar nada. Un README sin instrucciones claras hace que el proyecto no se pueda evaluar ni usar.

Paso 5Crear README.md en la raíz del proyecto
README.md — raíz del proyecto
El README es un documento Markdown — se ve formateado en GitHub, GitLab y en VS Code. Usa # para títulos, **texto** para negritas y bloques de código con tres backticks. No es un archivo de código — es documentación.

7 Preguntas de reflexión final
  1. Describe en tus propias palabras la arquitectura del sistema que construiste: qué capas tiene, qué tecnología usa cada capa y cómo se comunican entre sí. Incluye los mecanismos de seguridad en cada capa.
  2. De todos los conceptos nuevos que aprendiste en este proyecto (JWT, bcrypt, RBAC, REST, React, validaciones, auditoría, etc.), ¿cuál fue el más difícil de entender y cuál fue el que más te sorprendió? Justifica ambas respuestas.
  3. Si tuvieras que agregar un módulo completamente nuevo al sistema — por ejemplo, un módulo de "Clientes" con su CRUD completo y sus relaciones — ¿qué archivos crearías y en qué orden? Describe los pasos sin escribir código.
  4. El sistema tiene autenticación con JWT y cookie httpOnly, bcrypt para contraseñas, RBAC para permisos, validaciones con express-validator, helmet, rate limiting, CAPTCHA y auditoría. ¿Qué vulnerabilidad importante crees que todavía no está cubierta y cómo la resolverías?
  5. ¿Cómo cambiaría el sistema si en lugar de XAMPP local tuvieras que desplegarlo en un servidor real en internet? Menciona al menos 4 cambios técnicos que serían necesarios.
